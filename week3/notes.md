# Week 3：演算法

## O、Ω、Θ 三個概念

### 一句話理解
- O（big O）：最多要幾步 → 上界，CS50 用來描述「最壞情況」
- Ω（big Omega）：最少要幾步 → 下界，CS50 用來描述「最好情況」
- Θ（big Theta）：最多和最少一樣 → 上下界相同，不管輸入如何成長趨勢都一樣

### 比喻：通勤時間
- 塞車最嚴重時 60 分鐘 → O
- 一路綠燈時 20 分鐘 → Ω
- 搭捷運，每天都是 30 分鐘 → Θ
- 只有 O 和 Ω 相同時，才能用 Θ 描述

### 共同原則
- 看的是「n 變大時的成長趨勢」，不是精確步數
- 忽略常數倍數：n/2 和 n 都是 O(n)
- 忽略次要項：n² + n 寫成 O(n²)，因為 n 很大時 n² 主導一切

### 用自己寫過的程式對照
| 程式 | O（最壞） | Ω（最好） | Θ | 說明 |
|------|------|------|------|------|
| search_number 線性搜尋 | O(n) | Ω(1) | 無 | 最壞找遍全部；最好第一個就是 |
| 二分搜尋 | O(log n) | Ω(1) | 無 | 最壞減半到剩 1 個；最好第一次看中間就是 |
| check_prime（i * i <= n） | O(√n) | Ω(1) | 無 | 質數要試完；偶數在 i = 2 就結束 |
| strlen / 數陣列元素個數 | O(n) | Ω(n) | Θ(n) | 不管內容如何都要走到最後 |
| sec1_07 power(m, n) | O(n) | Ω(n) | Θ(n) | 迴圈固定跑 n 次 |
| 用索引取 numbers[3] | O(1) | Ω(1) | Θ(1) | 直接算出位置，和陣列大小無關 |
| cash（用 / 和 %） | O(1) | Ω(1) | Θ(1) | 固定 4 種硬幣、固定步數，和金額大小無關 |
| mario 金字塔（高度 n） | O(n²) | Ω(n²) | Θ(n²) | 約 n²/2 個字元，忽略常數後是 n² |

### 常見誤解
- Θ 不是「平均情況」，而是「最好和最壞的成長趨勢相同」
- 有 Θ 的演算法不代表比較快：mario 是 Θ(n²)，線性搜尋只有 O(n)
- 嚴格的數學定義中，O / Ω / Θ 描述的是「上界／下界／兩者」，最壞和最好情況是另一個維度；CS50 為了好理解，直接把 O 對應最壞、Ω 對應最好

### 實務提醒
- 迴圈條件寫 i < strlen(s) 會讓 O(n) 變成 O(n²)，因為每圈都重新數一次（week2 string.c）
- Java 對照：ArrayList.get(i) 是 Θ(1)；ArrayList.contains() 是 O(n)、Ω(1)

## 補充與連結（官方筆記之外）
- 線性搜尋比較的是「每個位置存放的數值」，不是索引：輸入 5 會找到，是因為某個位置存了 5
- 二分搜尋：資料量加倍，線性搜尋的次數也加倍，二分搜尋只多 1 次

| 資料量 n | 線性搜尋最多 | 二分搜尋最多 |
|------|------|------|
| 1,000 | 1,000 次 | 10 次 |
| 1,000,000 | 1,000,000 次 | 20 次 |
| 10 億 | 10 億次 | 30 次 |

- 二分搜尋的停止條件「沒有門可以找了」不能少，否則找不到時會停不下來
- 計算中間位置寫 low + (high - low) / 2，比 (low + high) / 2 安全，避免整數溢位（Week 1 溢位觀念）
- 大 O 忽略常數倍數的理由：換一台快兩倍的電腦也能達到 n/2 的效果，真正的差別在曲線形狀
- Θ 的例子：數陣列有幾個元素，不管內容如何都要數完，所以是 Θ(n)
- Week 1 質數判斷的 i * i <= n 優化，是把 O(n) 降到 O(√n)

## 觀念補充

### sizeof 算陣列長度
- sizeof 量的是 byte 數，不是元素個數
- int numbers[7]：sizeof(numbers) 是 28，sizeof(numbers[0]) 是 4，相除得 7
- 用 numbers[0] 而不是 int：陣列型別改變時長度仍正確
- char 陣列的元素剛好 1 byte，sizeof 才等於元素數（且包含結尾 \0）
- 傳進函式後失效：參數只是位址，sizeof 得到 8，算出長度 2；clang 會警告，-Werror 下編譯失敗
- 解法：函式多加 length 參數，int search(int numbers[], int length, int n)

### strcmp：比較字串內容

#### 為什麼不能用 ==
- string 存的是「位址」，不是內容；== 比較的是兩個位址是否相同
- 兩次 get_string 都輸入 ABC，會在 heap 上各配置一塊記憶體，位址不同，所以 a == b 為假
- c = a 只複製位址，c 和 a 指向同一塊記憶體，所以 a == c 為真
- 字串常值 "ABC" == "ABC" 可能剛好為真（編譯器可能共用同一份），「有時對、有時錯」最危險
- 觀察位址：printf("%p\n", (void *) a);（每次執行位址都不同，是作業系統的安全機制）

#### 位址 vs 參考
- C 的位址（指標）和 Java 的參考扮演相同角色：變數不裝內容，而是記錄內容在哪裡
- 差別：C 的位址看得到（%p）、能做運算、可能指向無效記憶體；Java 的參考看不到、不能運算、只會是有效物件或 null
- string 就是 char * 的別名，* 代表「這是一個位址」

#### 回傳值
| 回傳值 | 意義 |
|------|------|
| 0 | 內容完全相同 |
| 負數 | 第一個字串排在前面 |
| 正數 | 第一個字串排在後面 |

- 運作方式：逐字元比較，遇到第一個不同的字元就比 ASCII 碼，誰小誰在前，立刻結束
- 只保證正負號，不保證是 -1 或 1；判斷時寫 < 0、> 0、== 0

#### 例子
| 呼叫 | 結果 | 原因 |
|------|------|------|
| strcmp("ABC", "ABD") | 負數 | 第 3 個字元 'C'(67) < 'D'(68) |
| strcmp("AB", "ABC") | 負數 | "AB" 結尾的 \0(0) < 'C'(67)，短的排前面 |
| strcmp("Zebra", "apple") | 負數 | 大寫 'Z'(90) < 小寫 'a'(97) |
| strcmp("10", "9") | 負數 | 比的是字元 '1'(49) < '9'(57)，不是數值大小 |
| strcmp("apple", "Apple") | 正數 | 區分大小寫，'a'(97) > 'A'(65) |

#### 容易出錯的地方
- if (strcmp(a, b)) 是「不相等時」才成立（相等回傳 0 = 假），一律明確寫 == 0
- 不要寫 == -1 或 == 1（和「判斷真假不要寫 == 1」同一個道理）
- 大寫永遠排在小寫前面，和字典順序不同
- 數字字串照字元比較，"10" 排在 "9" 前面
- 需要 #include <string.h>

#### 執行時間
- O(n)：最壞要比到字串結尾
- Ω(1)：第一個字元就不同時立刻結束

#### Java 對照
| Java | C | 說明 |
|------|------|------|
| a == b | a == b | 都是比較參考／位址，不是內容 |
| a.equals(b) | strcmp(a, b) == 0 | 比較內容是否相同 |
| a.compareTo(b) | strcmp(a, b) | 負數、0、正數表示先後順序 |
| a.equalsIgnoreCase(b) | strcasecmp(a, b) == 0 | 需 <strings.h>，POSIX 提供，不屬於標準 C |

- Java 寫字串要用 equals 的直覺，在 C 換成 strcmp(...) == 0 即可
- 正負號的主要用途是排序（Lecture 3 後半），和 Java 的 Comparator 是同一個概念

### struct：把相關的資料打包在一起

#### 是什麼
- 自訂一個新的資料型別，裡面可以包含多個欄位（成員）
- typedef 幫它取一個型別名稱，之後就能像 int 一樣直接宣告

#### 可以存放什麼
- 任何型別都可以當欄位，而且可以混合：int、double、char、string、陣列，甚至另一個 struct

    typedef struct
    {
        string name;    // 字串
        int age;        // 整數
        double gpa;     // 浮點數
    } student;

    student s;
    s.name = "Kurt";
    s.age = 30;
    s.gpa = 3.8;

- 用 . 存取欄位：s.name、s.age
- 宣告時直接初始化（指定初始化，C99）：
  student s = {.name = "Kurt", .age = 30, .gpa = 3.8};

#### 特性
- 是「值」不是「參考」：指定（b = a）和傳進函式都會複製整份內容
  - 函式裡改了 struct 的欄位，呼叫端不受影響（和 int 一樣）
  - 要讓函式改到原本的 struct，需傳位址（指標），用 -> 存取（Lecture 4、5）
- 沒有方法、沒有建構子、沒有封裝，欄位全部公開
- 宣告後欄位是垃圾值（區域變數），要自己指定或用初始化列表
- 不能用 == 比較兩個 struct，要逐欄比較（字串欄位還要用 strcmp）
- 欄位在記憶體中連續排放；sizeof(student) 可能比各欄位加總大，因為編譯器會為了對齊補空位（padding）

#### 什麼時候用
- 一筆資料有多個相關屬性時：person（名字、電話）、student（名字、年齡、成績）、point（x、y）
- 取代平行陣列：people[i].name 和 people[i].number 綁在一起，不會因為兩個陣列長度不一致而越界（phonebook.c → phonebook_struct.c）
- 函式需要回傳多個值時：C 的函式只能回傳一個值，但可以回傳一個 struct
- 函式參數太多時：把相關參數打包成一個 struct 傳入
- 後續課程：Lecture 4 讀寫 BMP 圖檔的標頭、Lecture 5 鏈結串列的節點（node），都是用 struct 描述

#### Java 對照
| | C struct | Java record | Java DTO |
|------|------|------|------|
| 用途 | 打包資料 | 打包資料 | 打包資料 |
| 方法 | 不能有 | 可以有 | 可以有 |
| 可否修改 | 可以 | 不可以 | 可以 |
| 指定、傳參數 | 複製整份內容 | 複製參考 | 複製參考 |
| 比較內容 | 逐欄比較 | equals 自動比較 | equals 要自己寫 |

- 一句話：struct 在「用途」上像 DTO 或 record，在「行為」上像 int
- Java 的 new Person[3] 每格是 null，要再 new；C 的 person people[3] 宣告完三個 person 就存在了
- 程式：phonebook_struct.c

## 遞迴（recursion）

### 是什麼
- 函式呼叫自己，把大問題變成「形狀相同、規模更小」的問題
- 由兩部分組成，缺一不可：
  - 基本情況（base case）：問題小到可以直接回答，不再呼叫自己，負責讓遞迴停下來
  - 遞迴情況（recursive case）：呼叫自己處理更小的問題，每次都要更接近基本情況
- 二分搜尋就是遞迴：「搜尋左半邊」= 把同一個方法套用在一半的範圍上
- 比喻：電影院太暗，問前一排的人坐第幾排，一路問到第 1 排（基本情況），答案一路加 1 傳回來

### 執行過程：draw(4)
- 每次呼叫都有自己的 n，呼叫 draw(n - 1) 時，自己暫停在那一行等它結束
- 第一階段（往下）：draw(4) → draw(3) → draw(2) → draw(1) → draw(0)，畫面上還沒有任何輸出
- draw(0) 是基本情況，直接 return
- 第二階段（往回）：回到 draw(1) 印 1 個 #，回到 draw(2) 印 2 個，… 最後 draw(4) 印 4 個
- 最先被呼叫的 draw(4) 反而最後才印

    draw(4)
    │ draw(3)
    │ │ draw(2)
    │ │ │ draw(1)
    │ │ │ │ draw(0) → return
    │ │ │ └ 印 #
    │ │ └ 印 ##
    │ └ 印 ###
    └ 印 ####

### 呼叫的位置決定結果
- draw(n - 1) 放在印出「之前」：往回的途中才印 → 正金字塔（1、2、3、4）
- draw(n - 1) 放在印出「之後」：往下的途中就印 → 倒金字塔（4、3、2、1）
- 合併排序也是靠這個特性：先遞迴排好兩半，往回時才合併

### 注意
- 少了基本情況，或遞迴情況沒有讓問題變小，會無限呼叫自己，最後耗盡記憶體讓程式崩潰（stack overflow，Lecture 4 講原因）
- Java 對照：概念完全相同；Java 會丟出 StackOverflowError，C 通常直接崩潰（Segmentation fault）
- 迴圈能做的事遞迴都能做，反之亦然；選擇的依據是哪種寫法比較自然
- 程式：recursion.c

## 排序（sorting）

### 選擇排序（selection sort）
- 做法：每一輪從「還沒排好的部分」找出最小的，換到最前面
- 例：[5, 2, 4, 1]
  - 第 1 輪：最小是 1，和 5 交換 → [1, 2, 4, 5]
  - 第 2 輪：剩下 [2, 4, 5] 最小是 2，不動
  - 第 3 輪：剩下 [4, 5] 最小是 4，不動
- 比較次數：(n-1) + (n-2) + … + 1 = n(n-1)/2，約 n²/2
- 就算一開始已經排好，每一輪還是要掃完剩下的部分才能確定誰最小
- O(n²)、Ω(n²)、Θ(n²)

### 泡沫排序（bubble sort）
- 做法：從頭到尾比較相鄰的兩個，順序錯了就交換；每一輪最大的會「浮」到最後
- 例：[5, 2, 4, 1]
  - 第 1 輪：5↔2、5↔4、5↔1 → [2, 4, 1, 5]（5 到最後）
  - 第 2 輪：2 和 4 不動、4↔1 → [2, 1, 4, 5]
  - 第 3 輪：2↔1 → [1, 2, 4, 5]
- 優化：某一輪完全沒有交換，代表已經排好，可以提早結束
- 所以已經排好的資料只要掃一輪就結束
- O(n²)、Ω(n)

### 合併排序（merge sort）
- 做法（遞迴）：
  - 基本情況：只剩 1 個元素，本身就是排好的
  - 遞迴情況：把陣列切成兩半，各自排序，再把兩個排好的半邊合併
- 合併兩個排好的陣列：各看最前面一個，小的先拿，直到兩邊拿完
- 例：[5, 2, 4, 1]
  - 切成 [5, 2] 和 [4, 1]，再切成 [5] [2] [4] [1]
  - 合併成 [2, 5] 和 [1, 4]
  - 合併 [2, 5] 和 [1, 4]：1、2、4、5 → [1, 2, 4, 5]
- 為什麼是 n log n：一直對半切，共切 log n 層；每一層合併時，所有元素各被看過一次，是 n
- 代價：合併時需要額外的陣列空間（用記憶體換時間）
- O(n log n)、Ω(n log n)、Θ(n log n)

### 比較
| 演算法 | O（最壞） | Ω（最好） | 特點 |
|------|------|------|------|
| 選擇排序 | O(n²) | Ω(n²) | 不管資料如何都要掃完 |
| 泡沫排序 | O(n²) | Ω(n) | 已排好時可提早結束 |
| 合併排序 | O(n log n) | Ω(n log n) | 最快，但需要額外記憶體 |

| n | n²（選擇、泡沫最壞） | n log n（合併） |
|------|------|------|
| 1,000 | 1,000,000 | 約 10,000 |
| 1,000,000 | 1 兆 | 約 2,000 萬 |

- Java 對照：Collections.sort 和 Arrays.sort（物件）使用 TimSort，是合併排序的改良版，O(n log n)；實務上直接用內建排序，不需要自己寫

## 踩過的坑

### 測試要包含邊界位置
- 搜尋程式除了測中間的值和不存在的值，也要測第一個和最後一個
- 長度算錯（off-by-one）時，通常是最後一個找不到

## 待解問題
- [x] 先排序、換取之後搜尋變快，什麼時候值得？
  - 排序一次的代價是 O(n log n)；之後每次搜尋從 O(n)（線性）降到 O(log n)（二分）
  - 只搜尋一次：不值得，直接線性搜尋 O(n) 比排序 O(n log n) 還快
  - 要搜尋很多次：值得。n = 1,000,000 時，log n 約 20，搜尋超過約 20 次左右，排序的成本就回收了
  - 資料經常變動時，每次變動都可能要重新排序，好處會打折
  - 結論：取決於「搜尋次數」和「資料多常改變」，這是用一次性的成本換取之後每次的速度
- [x] 遞迴是什麼？
  - 函式呼叫自己，把問題縮小到基本情況再一路往回組合答案（見上方「遞迴」段落）
