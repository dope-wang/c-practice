## 觀念補充

### 整數與浮點數的範圍（K&R 2.1、習題 2-1）

#### 我的機器實際印出的範圍（ARM 64 位元 Linux）
| 型別 | 最小值 | 最大值 |
|------|------|------|
| char | 0 | 255 |
| signed char | -128 | 127 |
| unsigned char | 0 | 255 |
| short | -32768 | 32767 |
| unsigned short | 0 | 65535 |
| int | -2147483648 | 2147483647 |
| unsigned int | 0 | 4294967295 |
| long | -9223372036854775808 | 9223372036854775807 |
| unsigned long | 0 | 18446744073709551615 |

- 整數範圍在 <limits.h>（CHAR_MIN、INT_MAX、ULONG_MAX…）；浮點數在 <float.h>（FLT_MAX、DBL_MAX…）
- 程式：ex2_01_datatype_size.c

#### 範圍會隨平台不同
- C 標準只規定「最少多大」，實際大小由平台決定
- 標準保證：char 至少 8 位元、short 和 int 至少 16、long 至少 32、long long 至少 64；且 short ≤ int ≤ long ≤ long long

| 平台 | char | int | long | 位址（指標） |
|------|------|------|------|------|
| x86 64 位元 Linux | 有號 | 4 bytes | 8 bytes | 8 bytes |
| ARM 64 位元 Linux（我的虛擬機） | **無號** | 4 bytes | 8 bytes | 8 bytes |
| ARM 64 位元 macOS（Apple Silicon） | 有號 | 4 bytes | 8 bytes | 8 bytes |
| 64 位元 Windows | 有號 | 4 bytes | **4 bytes** | 8 bytes |
| 32 位元系統 | 依平台 | 4 bytes | 4 bytes | 4 bytes |

- 一般的 char 是有號還是無號，C 標準沒有規定：同樣是 ARM，Linux 無號、macOS 有號
- 網路文件寫 CHAR_MIN = -128 只是 x86 的常見值；文件說明欄的規則才是標準：char 能表示負數時等於 SCHAR_MIN，否則是 0
- 「文件上的數字是某個平台的例子，說明裡的規則才是標準」
- 實務做法：
  - 需要確定有號或無號，明確寫 signed char 或 unsigned char
  - 需要確定位元數，用 <stdint.h> 的固定寬度型別：int8_t、uint8_t、int32_t、uint32_t、int64_t
  - 需要知道大小，用 sizeof 確認，不要假設
- Java 對照：Java 所有型別大小固定、與平台無關（byte 8 位元有號、char 16 位元無號、int 32、long 64）

#### 浮點數範圍的兩個陷阱
- 用 %f 印 FLT_MIN 會得到 0.000000：%f 只印到小數第 6 位，FLT_MIN 約 1.17e-38，要用 %e 或 %g
- FLT_MIN 不是最小值，而是「最接近 0 的正數」；float 真正的最小值是 -FLT_MAX（正負範圍對稱）
- 對照：整數的 INT_MIN 才是真正的最小值

#### 直接計算邊界值（習題 2-1 後半，需要 2.9 位元運算）
- 無號最大值：所有位元都是 1，~0 把 0 的每個位元反轉 → (unsigned char) ~0 = 11111111 = 255
- 有號最大值：無號最大值往右移一位，左邊補 0 → 11111111 >> 1 = 01111111 = 127
- 有號最小值：-最大值 - 1 = -128（不能用「最大值 + 1」，有號溢位是未定義行為）

### 二補數（two's complement）：有號整數怎麼表示負數

#### 最左邊的位元：判斷正負，而且代表負的位值
- 最左邊是 1 一定是負數、是 0 一定是零或正數（這點沒錯）
- 但其餘位元不是「大小」：最左邊那一位的位值是負的

| 位置 | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
|------|------|------|------|------|------|------|------|------|
| 無號的位值 | 128 | 64 | 32 | 16 | 8 | 4 | 2 | 1 |
| 有號的位值 | **-128** | 64 | 32 | 16 | 8 | 4 | 2 | 1 |

- 換算：是 1 的位置，位值加起來
  - 11111011 = -128 + 64 + 32 + 16 + 8 + 2 + 1 = -5
  - 若誤以為「最左邊只是負號、其餘是大小」，會算成 -123
- 同樣 8 個位元，無號時最左邊是 +128，有號時是 -128，這是兩者唯一的差別

| 二進位 | 有號 | 無號 |
|------|------|------|
| 00000000 | 0 | 0 |
| 01111111 | 127（最大） | 127 |
| 10000000 | -128（最小） | 128 |
| 11111111 | -1 | 255 |

#### 里程表比喻
- 000 倒退一格變 999；二進位 00000000 倒退一格變 11111111，所以是 -1
- 11111110 = -2，10000000 = -128（從 0 往回 128 格）

#### 正數轉負數：反轉再加 1
- 5 = 00000101 → 反轉 11111010 → 加 1 = 11111011 = -5

#### 為什麼這樣設計
- 加法不用分正負：00000101 + 11111011 = 1 00000000，只留 8 位得 0，硬體用同一套加法電路
- 只有一個 0（不會有 +0 和 -0），所以負數比正數多一個，範圍是 -128 ～ 127
- C23 起標準正式規定有號整數使用二補數（之前實務上也幾乎都是）

#### 和溢位的關係（連結 Week 1）
- 01111111 + 1 = 10000000，127 加 1 在硬體上變成 -128，就是 Week 1 dollars.c 觀察到的「變成負數」
- 但 C 標準規定有號溢位是未定義行為，編譯器不保證一定這樣繞回；無號溢位才保證繞回（255 + 1 = 0）
